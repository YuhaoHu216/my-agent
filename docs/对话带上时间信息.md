# 方案：Redis 聊天记忆添加时间信息

## 上下文

当前 `SlimMessage` 只存储 `role` 和 `text`，没有时间戳。前端加载历史消息时 `time` 字段硬编码为空字符串，只有新发送的消息用客户端 `getCurrentTime()` 生成时间。

**目标**：每条存入 Redis 的消息带上时间戳，前端历史消息可以显示时间。

## 变更文件

### 1. `RedisChatMemory.java`（后端）
**路径**：`src/main/java/space/huyuhao/myagent/chatmemory/RedisChatMemory.java`

**改动点**：

**a) SlimMessage 添加 timestamp 字段**
- 第31行：record 从 `(String role, String text)` 改为 `(String role, String text, Long timestamp)`
- 使用 `Long`（对象类型）而非 `long`：旧数据反序列化时 timestamp 为 null，前端可区分"无时间"和"时间为0"
- `@JsonIgnoreProperties(ignoreUnknown = true)` 已存在，天然向后兼容

**b) SlimMessage.from() 设置时间戳**
- 第40-49行：在工厂方法中捕获 `System.currentTimeMillis()` 传入 SlimMessage 构造函数
- 时间戳在消息持久化时设置，反映消息实际到达后端的时间

**c) ConversationSummary 使用真实时间戳**
- 第264-272行：`lastActivityTime` 优先从最后一条消息的 `timestamp` 字段获取
- 如果 timestamp 为 null（旧数据），回退到原来的 TTL 推算方式

### 2. `ChatRoom.vue`（前端）
**路径**：`d:\Code\fullstack\my-agent\frontend\my-agent-frontend\src\views\ChatRoom.vue`

**改动点**：

**a) 新增 formatTimestamp 辅助函数**
- 在 `getCurrentTime()`（第286行）附近添加，将毫秒时间戳转为 `HH:MM` 格式
- timestamp 为 null/undefined 时返回空字符串

**b) 两处消息映射使用后端时间**
- `enterSession()` 第487行：`time: ''` → `time: formatTimestamp(msg.timestamp)`
- `onMounted()` 第670行：`time: ''` → `time: formatTimestamp(msg.timestamp)`

### 不需要改动的文件
- `ChatMemoryController.java` / `ChatMemoryServiceImpl.java` — Jackson 自动序列化新字段
- `chatMemory.js` — API 响应自动包含新字段

## 向后兼容

- 旧 Redis 数据无 `timestamp` → Jackson 反序列化为 `null` → 前端显示空字符串（与现有一致）
- ConversationSummary 的 `lastActivityTime` 有 null 回退到 TTL 的逻辑

## 验证

1. 后端编译通过：`mvn compile`
2. 发送新消息后，检查 Redis 中 JSON 是否包含 `"timestamp":1754342400000`
3. 前端加载历史会话，消息时间显示为 `HH:MM` 格式
4. 旧会话（无 timestamp 数据）加载不报错，时间显示为空
