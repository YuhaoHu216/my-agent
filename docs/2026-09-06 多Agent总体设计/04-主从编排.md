# 阶段 04：主从编排（Orchestrator）

> 日期：2026-09-06
> 依赖：阶段 02、03（agent 定义 + AgentExecutor 已可用）。
> 目标：多个 agent 组合起来 —— 一个主 agent（编排器）根据任务动态决定调用哪个子 agent，子 agent 各自独立执行并返回结果，主 agent 汇总。
> 前置阅读：`00-多Agent机制-总体设计.md`、`02-自定义Agent管理.md`、`03-Agent单聊对话.md`

## 1. 背景与目标

主从编排形态（已确认）：用户创建一个**编排器**，绑定若干**子 agent**（阶段 02 创建的）。对话时用户与编排器聊天，编排器实时判断「当前任务该调用哪个子 agent」，并把子 agent 的输出作为上下文继续处理，最终给出综合结果。

与「顺序流水线」的区别：调用顺序由编排器 LLM 动态决定，不是写死的 A→B→C。

## 2. 架构与核心机制

### 2.1 核心思想：子 agent 即工具

复用一个关键事实：`ToolCallAgent` 已经支持「模型决策→调用工具→工具返回→继续思考」的循环。**把一个子 agent 包装成一个工具**（`AgentInvocationTool`）：

- 工具名：`run_agent__<agentId>`（唯一，便于模型选择）。
- 工具描述：该子 agent 的「职责摘要」（来自 `user_agent` 的 `system_prompt` 截断，或单独加一个 `description` 字段，见 §5 注意点）。
- 工具参数：`task`（要交给子 agent 的任务文本）。
- 执行：调用 `AgentExecutor` 以**非流式 run()** 运行子 agent，返回其结果文本 → 成为 `tool_result` 回到编排器上下文。

如此，编排器本身就是一个 `ToolCallAgent`，它的 `availableTools` = `系统工具 + MCP工具 + [每个子agent一个run_agent__工具]`。模型在 think 阶段自然知道「该不该把任务委派给某个子 agent」。

### 2.2 执行流程

```
用户消息 → /ai/orchestrator/chat?orchestratorId=&message=&chatId=
   ↓
OrchestratorService.load(orchestratorId)  // 归属校验 + enabled
   ↓
组装编排器 ToolCallAgent：
  systemPrompt = orchestrator.prompt + 子agent职责清单（自动附加）
  tools = allTools + executor为每个绑定子agent生成的 AgentInvocationTool
  modelChosen = orchestrator provider/modelName
   ↓
runStream(message, chatId)  ← 完全复用现有 AgentStepEvent SSE 协议
  ├─ think:模型判断是否委派子agent
  ├─ tool_call: 选中 run_agent__<id>
  ├─ act → AgentInvocationTool.execute(task)
  │      └─ AgentExecutor built 子agent实例 → run(task) → 最终文本
  ├─ tool_result: 子agent输出
  ├─ think:编排器消化子agent输出，决定继续委派 or doTerminate
  └─ …循环直至 finish
```

### 2.3 子 agent 执行细节

- 子 agent 用 `AgentExecutor.buildAgent(userId, agentId, null)` 构建，然后**非流式** `run(task)`，返回聚合文本（与 manus 非流式 `run` 行为一致）。
- 子 agent 内部仍会加载它自己绑定的 skill / mcp 工具 → 嵌套能力自然获得。
- 子 agent 的 `maxSteps` 用默认 20；`run()` 一次性执行完，不挂起。
- **记忆隔离**：子 agent 是临时实例、用内存 `messageList`（不写 Redis 会话），避免污染主对话历史。主编排器自己走 `runStream` 落库会话。
- **线程安全**：每次调用都 `new` 一个子 agent 实例，实例间无共享可变状态（`BaseAgent` 非单例），天然安全。

### 4.2 AgentInvocationTool（核心类）

Spring AI `ToolCallback` 接口（参考 `tool/TerminateTool.java` 附近的写法），需要实现 `getToolDefinition()` 与 `call(ToolExecutionRequest, Map<String,Object>)`。

```java
public class AgentInvocationTool implements ToolCallback {

    private final ToolDefinition toolDefinition;
    private final Long userId;        // 显式传入（子线程无 ThreadLocal）
    private final UserAgentService userAgentService;
    private final AgentExecutor agentExecutor;

    public AgentInvocationTool(Long userId, UserAgent agent,
                               UserAgentService uas, AgentExecutor ex) {
        this.userId = userId;
        this.userAgentService = uas;
        this.agentExecutor = ex;
        this.toolDefinition = ToolDefinition.builder()
            .name("run_agent__" + agent.getId())
            .description("将任务委派给子智能体【" + agent.getAgentName() + "】。"
                + "职责摘要：" + abbreviate(agent.getSystemPrompt(), 120)
                + "。参数 task 为要交给该子智能体的任务描述。")
            // 用 json schema 描述 task 参数
            .inputSchema(...);
    }

    @Override
    public ToolExecutionResult call(ToolExecutionRequest req, Map<String, Object> ctx) {
        String task = (String) req.arguments().get("task");
        UserAgent target = userAgentService.getValidated(userId, agentId);  // 归属校验
        String result = agentExecutor.runSync(userId, target, task); // 非流式 run
        return ToolExecutionResult.builder().output(result).build();
    }
}
```

> `AgentExecutor.runSync(userId, agent, task)`：`buildAgent(...)` 后 `return agent.run(task)`。

### 4.3 编排器装配

`OrchestratorExecutor`：

```java
public SseEmitter chat(Long userId, Long orchestratorId, String message, String chatId) {
    UserOrchestrator orch = orchestratorService.getValidated(orchestratorId);
    List<UserAgent> subAgents = orchestratorService.listAgents(orch.getId()); // enabled 的子agent
    // 编排器可用工具 = 系统工具 + 每个子agent一个 AgentInvocationTool（可选：+编排器绑定的MCP工具）
    List<ToolCallback> tools = new ArrayList<>();
    Collections.addAll(tools, allTools);
    for (UserAgent sub : subAgents) {
        tools.add(new AgentInvocationTool(userId, sub, userAgentService, agentExecutor));
    }
    ToolCallback[] toolArray = tools.toArray(new ToolCallback[0]);

    // 编排器提示词 = 编排器自己的 systemPrompt + 自动追加子agent清单
    String systemPrompt = orch.getSystemPrompt() + "\n\n\"你有以下可调用的子智能体：\""
        + subAgents.stream().map(a -> a.getId() + "." + a.getAgentName() + "：" + abbreviate(a.getSystemPrompt(), 50))
        .collect(Collectors.joining("\n"));

    // 模型 & ChatOptions
    ModelEnum modelEnum = ModelEnum.fromProvider(orch.getProvider());
    ChatModel chatModel = userChatModelManager.getChatModel(userId, modelEnum, orch.getModelName());
    ChatOptions chatOptions = modelRouter.createChatOptions(modelEnum, toolArray);

    // 装配编排器 = ToolCallAgent
    ToolCallAgent orchAgent = (ToolCallAgent) new ToolCallAgent(toolArray, chatOptions);
    orchAgent.setName(orch.getOrchestratorName());
    orchAgent.setUserId(userId);
    orchAgent.setVectorStore(vectorStore);
    orchAgent.setChatMemory(new RedisChatMemory(redisTemplate));
    orchAgent.setSystemPrompt(systemPrompt);
    orchAgent.setNextStepPrompt(promptProperties.getAgent().getNextStep());
    orchAgent.setRagPrefix/p/s/e(...);   // 编排器可带 RAG（用户文档）
    orchAgent.setMaxSteps(25);
    orchAgent.setChatClient(ChatClient.builder(chatModel).defaultAdvisors(new MyLoggerAdvisor()).build());
    return orchAgent.runStream(message, chatId);
}
```

要点：
- 编排器自己不绑 skill/MCP（或可选），关键是**子 agent 已在构建时带了各自的 skill/mcp**，编排器通过 `AgentInvocationTool` 间接调用。
- 子 agent 的 `AgentInvocationTool` 由 `AgentExecutor.buildAgent` 之外的独立工具类提供；`AgentInvocationTool` 内部调用 `AgentExecutor.runSync`。

## 7. 注意点

1. **记忆隔离**：子 agent `run()` 不落 Redis（`runStream` 才落库），编排器才落库。确认 `AgentExecutor.runSync` 用 `run()`（非流式且不调用持久化逻辑）。
2. **工具回传与截断**：子 agent 输出文本可能很长，作为 `tool_result` 回传时受 `truncateToolResult`（BaseAgent 已有截断）约束，无需额外处理。
3. **循环终止**：编排器最多 `maxSteps`(25)，超限强制 FINISHED（现有逻辑）；工具名唯一（`run_agent__<id>`）保证模型不会混淆。
4. **可选增强**：给 `user_agent` 加 `description`（一句话职责），让工具描述更精准而非截断 systemPrompt。本阶段用 `abbreviate(systemPrompt, …)` 兜底即可，加 description 列为可选项。
5. **前端 keep-alive**：对话页若加入编排器会话，沿用 AppLayout 的 `:include="['ChatRoom']"`，无需新增页面级 keep-alive 配置。
