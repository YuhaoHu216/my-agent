# RAG 多租户隔离 + 文档向量化信息/分片查看（2026-09-02 实现）

## Context

- 越权点 A：`BaseAgent.injectRagContext`（`agent/model/BaseAgent.java`）的 RAG 检索无 userId 过滤，会检索到所有用户的向量资料。
- 越权点 B：`app/MyApp.java` 三处 `QuestionAnswerAdvisor(vectorStore)` 同样无过滤。
- 前端 `Documents.vue` 有「存入向量数据库的文档信息」占位区（后端未实现）；且需要能看到每个文档被切分后的各 chunk 具体内容。

目标：
1. RAG 只能命中当前用户自己的资料（两处都隔离）。
2. 文档页能看到向量化信息与每个 chunk 的具体内容；最终收敛为单文档表，消除重复展示。

关键约束：RAG 检索运行在 `CompletableFuture.runAsync` / reactive 线程，`ThreadLocal` 不可靠；项目既有范式是 `UserContext.registerConversationUser(chatId)` + `getUserIdByConversationId(chatId)` 反查。隔离策略 = 显式传 userId + map 兜底 + 取不到用 `-1` fail-closed。

## 改动一：RAG 多租户隔离

- `agent/model/BaseAgent.java`：新增 `volatile Long userId` 字段；`injectRagContext` 检索改为带 `Filter(userId EQ)`，uid 取值：字段 → `getUserIdByConversationId(conversationId)` 兜底 → `-1` 封死。
- `agent/MyAgent.java`：`create(...)` 增加 `Long userId` 参数并 `setUserId`。
- `controller/AiController.java`：`doChatWithManus` 传入请求线程已取到的 userId。
- `app/MyApp.java`：新增 `userScopedRagSearch(chatId)` helper，三处 `new QuestionAnswerAdvisor(vectorStore, userScopedRagSearch(chatId))`。

## 改动二：文档向量化信息并入列表（单文档表）

- `dto/DocumentInfoDto.java` 增加字段 `vectorModel`（仅已向量化有值）、`vectorized`（= chunkCount>0）。
- `UserDocumentServiceImpl.list()` 填充两字段；`vectorModel` 读 `@Value("${dashscope.embedding.model}")`（text-embedding-v3）。
- 演进说明：最初实现过独立 `GET /document/vector/list` 与 `DocumentVectorInfoDto`，因与文档列表重复度高，界面合并为单表后**已移除**该接口、DTO、service 方法与前端 `vectorList()` api。

## 改动三：文档分片内容查看

- 新增 `dto/DocumentChunkInfoDto.java`：`chunkId/chunkIndex/totalChunks/title/content`。
- `UserDocumentService.chunks(id)` / 实现：先用 `selectByUserIdAndId` 做归属校验，再以 `userId + _source(filePath)` 取向量库中该文档全部分片并按 `chunkIndex` 排序；simple 模式反射遍历内部 `store`（同删除链路范式），milvus 模式用 `Filter(AND userId, _source)` + 足够大 topK 全量取回（备用存储，未启用）。
- `controller/UserDocumentController.java`：`GET /document/{id}/chunks`。
- 前端 `api/document.js` 新增 `chunks(id)`；`Documents.vue` 文档行新增「分块」按钮 → dialog 采用**左导航 + 右详情**两栏：左侧列出每片（第 N 片 / 标题 / 字数），右侧展示选中分片完整正文，支持上一片/下一片切换。

## 改动四：文档界面合并

- `Documents.vue` 移除「存入向量数据库的文档信息」独立板块；主文档表直接展示 文件名/大小/分块数/向量模型/向量化状态/上传时间/操作。
- 搜索态行（`DocumentSearchResultDto`）缺少 `vectorized` 时状态列显示 `-`，避免误标「未向量化」。

## 改动五：知识库 + 中转站双用途

- 新增 `config/DocumentProperties.java`（`my-agent.document.vectorizable-extensions`，默认 `md,txt`）：规定格式上传时向量化分片入知识库，其余扩展名文件仅存储到磁盘作为中转站。
- `UserDocumentServiceImpl.upload`：扩展名不限类型，任意文件均可上传存储；命中规定格式才读取内容、分块、`vectorStore.add` 并记 `chunkCount`，否则 `chunkCount=0`（仅存储）。
- `SimpleVectorStoreConfig`：启动扫描加载与上传共用 `DocumentProperties.vectorizableExtensionSet()`（不再各自硬编码，消除 .txt 双轨不一致）。
- 前端 `Documents.vue`：「向量化状态」列改为「用途」标签（已向量化 / 中转文件）；「分块」按钮仅对已向量化行显示。

## 验证

## 不改动 / 记录

未改向量库实现、分块/删除链路、DB 表结构。遗留观察点：`documentApi.search` 命中结果与主表格字段形态不一致（既有）；milvus 未启用，其 chunks 枚举为 filter+topK 近似实现。
