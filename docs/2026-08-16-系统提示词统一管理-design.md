# 系统提示词统一管理设计

日期：2026-08-16
状态：待实现

## 背景与目标

项目中的系统提示词（prompts）目前硬编码散落在多个 Java 文件中，修改提示词需要改代码、重新编译，难以维护。目标是将它们提取到独立 YAML 配置文件，通过 Spring `@ConfigurationProperties` 绑定注入，实现「改提示词只需改配置、无需改代码」。

本次纳入统一管理的提示词共 4 类：

| 提示词 | 当前位置 | 说明 |
|---|---|---|
| MyAgent 人设提示词 | `MyAgent.java` 的 `SYSTEM_PROMPT` | "你是MyAgent，一个全能的人工智能助手…" |
| MyAgent 下一步决策提示词 | `MyAgent.java` 的 `NEXT_STEP_PROMPT` | "如果用户没有提出具体需求…" |
| MyApp 对话提示词 | `MyApp.java` 的 `SYSTEM_PROMPT` 及报告拼接提示词 | "你是一个助理，master叫Guyue…" |
| RAG 上下文注入模板 | `BaseAgent.java` `injectRagContext()` | "以下是与用户问题相关的参考资料…" |

## 方案

采用「独立配置文件 + 单一配置类」：

- 新建 `src/main/resources/prompt.yml` 集中存放所有提示词。
- 新建 `PromptProperties` 配置类（沿用项目现有 `MilvusProperties` 的 `@Configuration + @ConfigurationProperties` 风格）绑定。
- `application.yml` 通过 `spring.config.import` 引入独立文件。
- `MyAgent` / `MyApp` / `BaseAgent` 统一从 `PromptProperties` 取用。

## 详细设计

### 1. 新建配置文件 `src/main/resources/prompt.yml`

```yaml
my-agent:
  prompt:
    agent:
      system: |
        你是MyAgent，一个全能的人工智能助手，旨在解决用户提出的任何任务。您可以使用各种工具来有效地完成复杂的请求。
        请全程使用中文，包括思考过程以及最终的结果输出。
        最终的结果输出请使用 Markdown 格式进行排版（如标题、列表、代码块、表格等）。
      next-step: |
        如果用户没有提出具体需求（如只说了"你好"或没有明确指令），请直接友好地回复询问用户需要什么帮助，然后立即调用 doTerminate 结束，不要擅自猜测或执行任何其他工具。
        只有在用户有明确需求时（如查天气、找地点、规划路线、下载文件等），才根据用户需求主动选择最合适的工具或工具组合。对于复杂的任务，您可以分解问题并逐步使用不同的工具来解决它。
        在使用每个工具后，清楚地解释执行结果并建议下一步。
    app:
      system: '你是一个助理,你的master叫 Guyue,你需要回答他的一些问题,他不喜欢长篇大论回答的时候可以加一些颜文字,比如 o((>ω< ))o,不要用emoji图标回答请使用 Markdown 格式进行排版（如标题、列表、代码块、表格等）'
      report-suffix: '每次对话后都要生成报告，标题为{用户名}的报告，内容为结果列表'
    rag:
      prefix: '以下是与用户问题相关的参考资料：'
      suffix: '可以选择性结合这些参考资料回答用户问题。如果答案不在参考资料中，请如实告知。'
      separator: '---'
```

### 2. 新建配置类 `config/PromptProperties.java`

沿用项目现有 `MilvusProperties` 风格（`@Configuration` + `@ConfigurationProperties` + Lombok），无需改动启动类。

```java
package space.huyuhao.myagent.config;

import lombok.Data;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.context.annotation.Configuration;

@Configuration
@ConfigurationProperties(prefix = "my-agent.prompt")
@Data
public class PromptProperties {

    private Agent agent = new Agent();
    private App app = new App();
    private Rag rag = new Rag();

    @Data
    public static class Agent {
        private String system;
        private String nextStep;
    }

    @Data
    public static class App {
        private String system;
        private String reportSuffix;
    }

    @Data
    public static class Rag {
        private String prefix;
        private String suffix;
        private String separator;
    }
}
```

### 3. 启用配置文件引入

`application.yml` 顶部（`spring:` 段内）增加：

```yaml
spring:
  config:
    import: prompt.yml
```

### 4. 各文件修改点

#### `MyAgent.java`

- 构造器新增 `PromptProperties promptProperties` 参数，删除两个硬编码的文本块。
- 用配置值设置人设与下一步提示词，并把 RAG 模板 set 到父类 `BaseAgent`：

```java
public MyAgent(ToolCallback[] allTools,
               ToolCallbackProvider toolCallbackProvider,
               ChatModel dashscopeChatModel,
               VectorStore vectorStore,
               RedisTemplate<String, byte[]> redisTemplate,
               PromptProperties promptProperties) {
    super(mergeToolCallbacks(allTools, (ToolCallback[]) toolCallbackProvider.getToolCallbacks()));
    this.setName("myManus");
    this.setVectorStore(vectorStore);
    this.setChatMemory(new RedisChatMemory(redisTemplate));
    this.setSystemPrompt(promptProperties.getAgent().getSystem());
    this.setNextStepPrompt(promptProperties.getAgent().getNextStep());
    this.setRagPrefix(promptProperties.getRag().getPrefix());
    this.setRagSuffix(promptProperties.getRag().getSuffix());
    this.setRagSeparator(promptProperties.getRag().getSeparator());
    this.setMaxSteps(20);
    ChatClient chatClient = ChatClient.builder(dashscopeChatModel)
            .defaultAdvisors(new MyLoggerAdvisor())
            .build();
    this.setChatClient(chatClient);
}
```

#### `BaseAgent.java`

- 新增三个字段（`@Data` 自动生成 setter）：

```java
// RAG 上下文注入模板（由子类从配置注入）
private String ragPrefix;
private String ragSuffix;
private String ragSeparator;
```

- `injectRagContext()` 中，将硬编码模板改为使用上述字段，拼接逻辑与原实现等价：

```java
String ragPrompt = ragPrefix + "\n\n" + context + "\n\n" + ragSuffix;
this.systemPrompt = ragPrompt + "\n\n" + ragSeparator + "\n\n" + this.systemPrompt;
```

#### `MyApp.java`

- 删除 `private static final String SYSTEM_PROMPT`，改为从配置读取。
- 构造器新增 `PromptProperties promptProperties` 参数，保存 `system` 与 `reportSuffix` 到实例字段：

```java
public MyApp(ChatModel dashscopeChatModel, RedisTemplate<String, byte[]> redisTemplate,
             PromptProperties promptProperties) {
    this.redisChatMemory = new RedisChatMemory(redisTemplate);
    this.systemPrompt = promptProperties.getApp().getSystem();
    this.reportSuffix = promptProperties.getApp().getReportSuffix();
    chatClient = ChatClient.builder(dashscopeChatModel)
            .defaultSystem(systemPrompt)
            .defaultAdvisors(
                    new MessageChatMemoryAdvisor(redisChatMemory),
                    new MyLoggerAdvisor()
            )
            .build();
}
```

- `doChatWithReport()` 中 `.system(SYSTEM_PROMPT + "...")` 改为 `.system(systemPrompt + reportSuffix)`。

#### `AiController.java`

- `MyAgent` 在 `doChatWithManus` 中被手动 `new`，需注入 `PromptProperties` 并传入：

```java
@Resource
private PromptProperties promptProperties;
// ...
MyAgent myAgent = new MyAgent(allTools, toolCallbackProvider, dashscopeChatModel, vectorStore, redisTemplate, promptProperties);
```

### 5. 行为保持说明

- `agent.system` / `agent.next-step` 使用 YAML 块标量 `|`，保留原 Java 文本块的换行结构。
- `app.system` 使用单行单引号字符串，保持原「无换行字符串拼接」的语义。
- `app.report-suffix` 中的 `{用户名}` 占位符原样保留（原代码本就未做替换）。
- RAG 拼接顺序 `prefix + context + suffix + separator + systemPrompt` 与原逻辑一致。
- `PromptProperties` 中的 `@Data` 会在配置缺失时让字段保持 null；`MyAgent` 首次 `think` 时 `nextStepPrompt` 为空会跳过注入（原逻辑已判空），`system` 为空会让 LLM 缺少人设——属配置错误，由启动/运行时暴露，不在本次范围内额外兜底。

### 6. 验证方式

- 仅执行 `mvn compile` 验证编译通过，不编写/运行测试（遵循项目规则）。
