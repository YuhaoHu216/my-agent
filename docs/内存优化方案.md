# 服务内存占用优化方案

> 日期：2026-08-11
> 问题：服务打包运行在 Linux 上占用 500+ MB 内存

---

## 问题分析

经分析，高内存占用主要由以下原因导致：

| # | 问题 | 影响程度 |
|---|------|----------|
| 1 | Dockerfile 无 JVM 内存参数，JVM 使用默认堆内存策略 | **严重** |
| 2 | 基础镜像使用完整 JDK (`eclipse-temurin:21`)，约 420MB | **严重** |
| 3 | 生产环境使用内存向量存储 (`SimpleVectorStore`)，所有文档+1024维向量加载到堆 | **严重** |
| 4 | Redis 聊天记忆无 TTL，数据永不过期持续增长 | 中等 |
| 5 | Spring Boot 全量自动配置，加载不必要的类 | 中等 |
| 6 | Agent 每次请求新建实例，消息列表累积 | 轻微 |

---

## 优化措施（按优先级排序）

### 1. JVM 内存参数调优

**文件**: `src/main/resources/docker/dockerfile`

**当前**:
```dockerfile
ENTRYPOINT ["java", "-jar", "/app.jar"]
```

**改为**:
```dockerfile
ENTRYPOINT ["java", \
    "-Xms256m", "-Xmx512m", \
    "-XX:+UseZGC", \
    "-XX:MaxDirectMemorySize=128m", \
    "-XX:ReservedCodeCacheSize=64m", \
    "-XX:+ExitOnOutOfMemoryError", \
    "-jar", "/app.jar"]
```

**参数说明**:
| 参数 | 说明 |
|------|------|
| `-Xms256m` | 初始堆内存 256MB |
| `-Xmx512m` | 最大堆内存 512MB（可根据压测调整到 768MB） |
| `-XX:+UseZGC` | 使用 ZGC（Java 21 的低延迟垃圾回收器） |
| `-XX:MaxDirectMemorySize=128m` | 限制 Netty/WebFlux 直接内存 |
| `-XX:ReservedCodeCacheSize=64m` | 减少 JIT 编译代码缓存 |

**预计减少**: 200-300MB

---

### 2. Docker 镜像瘦身

**文件**: `src/main/resources/docker/dockerfile`

**当前**: 使用完整 JDK 镜像 `eclipse-temurin:21`

**改为**: 使用 JRE Alpine 镜像 + 多阶段构建

```dockerfile
# 第一阶段：安装 Node.js 和 MCP 工具
FROM node:18.20.4-alpine AS node-builder
RUN npm install -g @amap/amap-maps-mcp-server

# 第二阶段：运行应用
FROM eclipse-temurin:21-jre-alpine
RUN apk add --no-cache nodejs npm tzdata
COPY --from=node-builder /usr/local/lib/node_modules /usr/local/lib/node_modules
COPY --from=node-builder /usr/local/bin/amap-maps-mcp-server /usr/local/bin/
ENV TZ=Asia/Shanghai
COPY ./backend/my-agent-0.0.1-SNAPSHOT.jar /app.jar
ENV SPRING_PROFILES_ACTIVE=prod
ENTRYPOINT ["java", "-Xms256m", "-Xmx512m", "-XX:+UseZGC", "-XX:MaxDirectMemorySize=128m", "-XX:ReservedCodeCacheSize=64m", "-XX:+ExitOnOutOfMemoryError", "-jar", "/app.jar"]
```

**说明**:
- `eclipse-temurin:21-jre-alpine` 约 180MB，比完整 JDK 少约 240MB
- Alpine 版本进一步减小镜像体积
- 多阶段构建将 Node.js/npm 工具复制到运行镜像

**预计减少**: ~200MB（镜像大小）

---

### 3. 生产环境向量存储切换为 Milvus

**文件**: `src/main/resources/application-prod.yml`

**当前**:
```yaml
vector:
  store:
    type: simple  # 内存向量存储
```

**改为**:
```yaml
vector:
  store:
    type: milvus  # 外部向量数据库
```

**说明**:
- Milvus 已在 Docker Compose 中部署（`docker-compose-milvus.yml`）
- 切换后向量数据存储在外部 Milvus 进程，释放 JVM 堆内存
- 不需要改代码，纯配置切换

**预计减少**: 100-200MB（堆内存）

---

### 4. Redis 聊天记忆添加 TTL

**文件**: `src/main/java/space/huyuhao/myagent/chatmemory/RedisChatMemory.java`

**问题**: `set()` 方法不设置过期时间，对话数据永不过期。

**修改**: 在保存时添加 7 天过期时间
```java
redisTemplate.opsForValue().set(key, bytes, 7, TimeUnit.DAYS);
```

同时对已有 key 通过 `expire()` 刷新 TTL。

**预计效果**: 防止 Redis 内存持续增长

---

### 5. Spring Boot 自动配置精简

**文件**: `src/main/java/space/huyuhao/myagent/MyAgentApplication.java`

**当前**:
```java
@SpringBootApplication(scanBasePackages = "space.huyuhao.myagent",
                       exclude = PgVectorStoreAutoConfiguration.class)
```

**改为**:
```java
@SpringBootApplication(scanBasePackages = "space.huyuhao.myagent",
                       exclude = {
                           PgVectorStoreAutoConfiguration.class,
                       })
```

同时在 `application.yml` 添加懒加载:
```yaml
spring:
  main:
    lazy-initialization: true
```

> ⚠️ 注意：懒加载会使首次请求延迟增加，需要评估是否适合生产环境。

**预计减少**: 30-50MB（类元数据 + Bean 实例）

### 6. 其他优化建议

#### 6.1 添加 `.dockerignore`

在项目根目录创建 `.dockerignore`:
```
target/
.git/
.gitignore
*.md
!README.md
.idea/
*.iml
.vscode/
node_modules/
uploads/
```

#### 6.2 Docker Compose 容器资源限制

**文件**: `src/main/resources/docker/docker-compose.yml`

```yaml
services:
  my_agent:
    # ... 其他配置
    deploy:
      resources:
        limits:
          memory: 768M
        reservations:
          memory: 256M
```

#### 6.3 数据库连接池调优

在 `application-prod.yml` 添加:
```yaml
spring:
  datasource:
    hikari:
      maximum-pool-size: 5      # 从默认10减少
      minimum-idle: 2           # 从默认10减少
      idle-timeout: 300000      # 5分钟
      max-lifetime: 600000      # 10分钟
```

#### 6.4 Agnet 实例复用

**文件**: `src/main/java/space/huyuhao/myagent/controller/AiController.java`

当前每次请求 `new MyAgent(...)`，可考虑使用对象池或单例模式（需确保无状态部分可复用）。

#### 6.5 日志轮转配置

创建 `src/main/resources/logback-spring.xml`:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <include resource="org/springframework/boot/logging/logback/defaults.xml"/>
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>logs/my-agent.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>logs/my-agent-%d{yyyy-MM-dd}.%i.log</fileNamePattern>
            <maxFileSize>50MB</maxFileSize>
            <maxHistory>7</maxHistory>
            <totalSizeCap>500MB</totalSizeCap>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>
    <root level="INFO">
        <appender-ref ref="FILE"/>
    </root>
</configuration>
```

## 预期效果总结

| 优化项 | 预计减少 | 难度 |
|--------|----------|------|
| JVM 参数调优 | 200-300MB 运行内存 | 低 |
| Docker 镜像瘦身 | ~200MB 镜像大小 | 中 |
| 向量存储切换 Milvus | 100-200MB 堆内存 | 低（仅配置） |
| Redis TTL | 防止持续增长 | 低 |
| 自动配置精简 | 30-50MB | 低 |
| **合计** | **运行内存控制在 300-400MB** | |

## 实施验证

1. `docker stats my_agent` 查看实际运行内存
2. 压测并发对话，观察内存是否稳定无泄漏
3. `redis-cli TTL <key>` 验证过期时间生效
4. Milvus Attu (`http://host:9091`) 确认向量数据正确存储
