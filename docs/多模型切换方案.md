# 多模型切换方案 — 添加 DeepSeek 支持

## 背景

当前项目仅支持阿里云 DashScope 作为 LLM 提供商，所有对话（MyApp 简单对话、MyAgent ReAct 智能体）都硬编码使用 `dashscopeChatModel`。用户需要在对话时能够动态切换不同的模型（如 DashScope Qwen 系列 和 DeepSeek）。

## 目标

- 添加 DeepSeek 模型支持（OpenAI 兼容 API）
- 前端增加模型选择下拉框，用户可在对话中选择模型
- 后端支持接收 `model` 参数，动态路由到对应的 ChatModel
- 保持现有 DashScope 功能不变，嵌入层不动

---

## 实现方案

### 一、pom.xml 依赖变更

添加 `spring-ai-openai` 核心库（不用 starter，避免自动配置冲突）：

```xml
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-openai</artifactId>
    <version>1.0.0-M6</version>
</dependency>
```

### 二、配置文件变更 (application.yml)

新增 DeepSeek 相关配置：

```yaml
spring:
  ai:
    deepseek:
      api-key: ${DEEPSEEK_API_KEY}
      base-url: https://api.deepseek.com
      chat:
        options:
          model: deepseek-chat
          timeout: 180000
```

环境变量 `DEEPSEEK_API_KEY` 需要设置。

### 三、新增文件

| 文件 | 说明 |
|------|------|
| `model/ModelEnum.java` | 模型枚举，定义支持的模型列表 (provider + modelName) |
| `config/DeepSeekConfig.java` | 手动创建 DeepSeek 的 `OpenAiChatModel` Bean |

### 四、修改文件

#### 4.1 `ToolCallAgent.java`

- 添加重载构造函数 `ToolCallAgent(ToolCallback[] availableTools, ChatOptions chatOptions)`
- 原无参构造函数委托到新构造函数，传入 DashScope 默认 ChatOptions
- 将 `chatOptions` 字段从硬编码改为构造函数注入

#### 4.2 `MyAgent.java`

- 构造函数新增 `ChatModel` 参数用于接收对应提供商的模型（不再固定用 `dashscopeChatModel`）
- 构造函数新增 `ModelEnum` 参数，通过 `ChatOptionsFactory` 生成对应的 ChatOptions 传给父类
- ChatClient 使用传入的 provider-specific ChatModel 构建

#### 4.3 `MyApp.java`

- 注入多个 ChatModel Bean（dashscopeChatModel + deepseekChatModel）
- 预构建每个 provider 的 ChatClient 实例（存入 Map）
- 每个对话方法新增 `ModelEnum model` 参数
- 方法内部根据 model 选择对应的 ChatClient 执行调用

#### 4.4 `AiController.java`

- 所有对话端点新增 `@RequestParam(defaultValue = "qwen-turbo") String model` 参数
- `/manus/chat` 端点根据 model 选择 provider-specific ChatModel 传给 MyAgent

#### 4.5 前端 `api/ai.js`

- `doChatWithLoveAppSse` 和 `doChatWithManus` 新增 `model` 参数
- 拼接到请求 URL query string 中

#### 4.6 前端 `views/ChatRoom.vue`

- 在 header 区域（chat/agent 模式切换旁边）添加模型选择下拉框 `el-select`
- 分组展示：DashScope (Qwen Turbo/Plus/Max) 和 DeepSeek (DeepSeek Chat)
- 新增 `selectedModel` ref，默认值 `qwen-turbo`
- `sendMessage()` 中传递 `selectedModel.value` 给 API 调用

---

## 模型路由策略

- **MyApp**：预构建多个 ChatClient（每个 provider 一个），请求时根据 model 参数选择
- **MyAgent**：每次请求 `new` 实例，直接传入 provider-specific ChatModel + ChatOptions
- **无 ThreadLocal**：避免 reactive 流跨线程问题，使用显式参数传递

## 验证方式

1. 编译检查：`./mvnw clean compile` 确保无编译错误
2. 启动应用后检查日志，确认 DeepSeek ChatModel Bean 创建成功
3. 前端测试：在 Chat 模式下切换模型，发送消息验证响应来自正确模型
4. 前端测试：在 Agent 模式下切换模型，验证 ReAct 循环正常执行
5. 检查 DashScope 模型仍正常工作（向后兼容）
