# 引入 DeepSeek 模型 + 模型切换方案

## 背景

当前项目只接入阿里云 DashScope（通义千问）作为 LLM，`MyApp`（Chat 模式）和 `MyAgent`（Agent/ReAct 模式）都硬编码使用 `dashscopeChatModel`。用户需要在对话时能切换模型（通义千问 ↔ DeepSeek）。

> 说明：DeepSeek 官方已于 2026-07-24 下线旧模型别名 `deepseek-chat` / `deepseek-reasoner`，新模型 ID 为 `deepseek-v4-pro` 与 `deepseek-v4-flash`（均支持工具调用）。因此 DeepSeek 侧模型名做成**配置文件可配**，不在代码里写死具体模型列表。

## 目标

- 后端接入 DeepSeek（OpenAI 兼容 API，`https://api.deepseek.com`）。
- 前端 header 增加模型选择下拉框（通义千问 / DeepSeek），Chat 与 Agent 两种模式共用。
- 选择持久化到 localStorage（与现有 `chatMode` 一致）。
- 通义千问侧保持现有默认模型不变；DeepSeek 侧模型名从 `application.yml` 读取（默认 `deepseek-v4-pro`）。
- 嵌入层（DashScope 向量化）不动。

## 模型标识约定

前端 `model` 参数传 `qwen` 或 `deepseek`，后端 `ModelEnum` 映射：

| code | 提供商 | 说明 |
|------|--------|------|
| `qwen` | DashScope | 现有默认模型，行为不变 |
| `deepseek` | DeepSeek | 模型名来自 `spring.ai.deepseek.chat.options.model` |

## 后端改动

### 1. `pom.xml` — 新增依赖

```xml
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-openai</artifactId>
    <version>1.0.0-M6</version>
</dependency>
```

> 注意：引入 `spring-ai-openai` 后，`spring-ai-spring-boot-autoconfigure` 中的 `OpenAiAutoConfiguration` 会因 `OpenAiApi` 出现在 classpath 上而被激活，自动创建 `openAiChatModel` / `openAiEmbeddingModel` 等 bean 并要求 `spring.ai.openai.api-key`，导致启动失败。因此 DeepSeek 的 `ChatModel` 由 `DeepSeekConfig` 手动创建，并在启动类排除 `OpenAiAutoConfiguration`（见第 10 节）。

### 2. `src/main/resources/application.yml` — 新增 DeepSeek 配置

```yaml
spring:
  ai:
    deepseek:
      api-key: ${DEEPSEEK_API_KEY}
      base-url: https://api.deepseek.com
      chat:
        options:
          model: ${DEEPSEEK_MODEL:deepseek-v4-pro}
```

### 3. 新增 `model/ModelEnum.java`

枚举 `QWEN(DASHSCOPE, "qwen")`、`DEEPSEEK(DEEPSEEK, "deepseek")`，含内部 `Provider` 枚举、`code` 字段，以及 `static ModelEnum fromCode(String code)`（未知值回退 `QWEN`）。

### 4. 新增 `config/DeepSeekConfig.java`

`@Bean("deepseekChatModel")` 手动创建 `OpenAiChatModel`（`OpenAiApi` + `OpenAiChatOptions.model(...)`）。

### 5. 新增 `model/ModelRouter.java`（`@Component`）

- 注入两个 `ChatModel`（`@Qualifier("dashscopeChatModel")`、`@Qualifier("deepseekChatModel")`），存 `Map<ModelEnum, ChatModel>`。
- `ChatModel getChatModel(ModelEnum)`。
- `ChatOptions createChatOptions(ModelEnum, ToolCallback[])`：
  - DashScope：`DashScopeChatOptions.builder().withProxyToolCalls(true).build()`（与现状一致）。
  - DeepSeek：`OpenAiChatOptions.builder().toolCallbacks(tools).internalToolExecutionEnabled(false).build()`（手动管理工具调用）。

### 6. `agent/ToolCallAgent.java` — 去掉硬编码

构造函数改为 `ToolCallAgent(ToolCallback[] availableTools, ChatOptions chatOptions)`，`chatOptions` 由调用方注入。

### 7. `agent/MyAgent.java` — 接收 provider 专属模型与 options

- 移除 `@Component`（该类仅被 `AiController` 手动创建，从未作为 Bean 注入，去掉冗余注解避免第二个 `ChatModel` Bean 出现后构造注入歧义）。
- 改为静态工厂 `MyAgent.create(...)`：合并工具、通过 `ModelRouter` 解析模型与 options 后构造。

### 8. `app/MyApp.java` — 按模型预建 ChatClient

- 构造函数注入 `ModelRouter`，遍历 `ModelEnum` 预建 `Map<ModelEnum, ChatClient>`（共享同一 `RedisChatMemory`）。
- `doChatByStream(String message, String chatId, ModelEnum model)` 新增 `model` 参数。
- `doChat` / `doChatWithReport` 内部用默认 `ModelEnum.QWEN`（前端未使用，保持原签名）。

### 9. `controller/AiController.java` — 端点接收 model

- 前端使用端点新增 `@RequestParam(defaultValue = "qwen") String model`：
  - `GET /ai/my_app/chat/sse/one` → `myApp.doChatByStream(message, chatId, ModelEnum.fromCode(model))`。
  - `GET /ai/manus/chat` → `MyAgent.create(..., ModelEnum.fromCode(model), ...)`。
- 其余未用端点（`/sync`、`/sse/two`、`/sse/emitter`）内部传 `ModelEnum.QWEN`。

### 10. `MyAgentApplication.java` — 排除 OpenAI 自动配置

在启动类的 `@SpringBootApplication` 上追加排除 `OpenAiAutoConfiguration`：

```java
import org.springframework.ai.autoconfigure.openai.OpenAiAutoConfiguration;

@SpringBootApplication(scanBasePackages = "space.huyuhao.myagent",
        exclude = {PgVectorStoreAutoConfiguration.class, OpenAiAutoConfiguration.class})
```

原因：引入 `spring-ai-openai` 后 `OpenAiAutoConfiguration` 被激活，会创建 `openAiEmbeddingModel` 等 bean 并要求 `spring.ai.openai.api-key`；本项目嵌入层仍走 DashScope，DeepSeek 的 `ChatModel` 由 `DeepSeekConfig` 手动创建，无需 OpenAI 自动配置。

## 前端改动

### 11. `src/api/ai.js`

`doChatWithLoveAppSse`、`doChatWithManus` 增加 `model` 参数，拼到 URL query。

### 12. `src/views/ChatRoom.vue`

- header 区域（模式切换旁）新增 `el-select` 模型下拉：`通义千问`(`qwen`)、`DeepSeek`(`deepseek`)。
- 新增 `selectedModel` ref，初值从 localStorage 读取（默认 `qwen`），切换时写回。
- `sendMessage()` 传递 `selectedModel.value`。

## 验证方式

1. `./mvnw clean compile`（后端编译通过）。
2. 前端 `npm run build`（编译通过）。
3. 人工验证（用户侧）：
   - 配置 `DEEPSEEK_API_KEY` 后启动，确认 `deepseekChatModel` Bean 创建成功。
   - Chat / Agent 模式分别切换模型验证。
   - 刷新页面确认模型选择被记住。

## 风险与注意

- DeepSeek Agent 模式工具调用用 `internalToolExecutionEnabled(false)` + `toolCallbacks(...)` 手动管理，DashScope 路径不变。
- 若用带思考模式的模型，工具调用循环可能需回传 `reasoning_content`，默认 `deepseek-v4-pro`（非思考）规避。
- `DEEPSEEK_API_KEY` 为必填环境变量（与现有 `ALI_API_KEY` 一致，未配置时应用启动失败，报 `Could not resolve placeholder 'DEEPSEEK_API_KEY'`）。
- 启动类已 `exclude` `OpenAiAutoConfiguration`，请勿删除该排除项，否则启动会因缺少 `spring.ai.openai.api-key` 失败（报 `openAiEmbeddingModel` 创建异常）。
