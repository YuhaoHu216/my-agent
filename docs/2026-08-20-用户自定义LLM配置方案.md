# 用户自定义 LLM 配置功能（api-key + 多模型）方案

## 背景

目前系统的 LLM api-key 和模型名全局写死在 `application.yml`（DashScope 用 `${ALI_API_KEY}`，DeepSeek 用 `${DEEPSEEK_API_KEY}`），所有用户共用一套。

**目标**：让每个登录用户自行配置 LLM 的 api-key 并指定模型名，配置存储到数据库，调用 LLM 时按用户使用其自己的 key 和模型。

**最终形态（用户确认）**：
- 一个供应商配置一个 api-key，该 key 下可配置多个模型名。
- 对话界面按「供应商分组」选择不同供应商下的不同模型。

## 已确认决策

1. 提供商：先支持现有两个（通义 DashScope + DeepSeek），数据结构预留扩展。
2. key 安全：明文存储 + 接口返回时脱敏（只显示 `****` + 后 4 位）。
3. 回退策略：**强制配置** —— 用户未配置 LLM 时，聊天接口提示先去配置，不用系统默认 key。
4. 模型名：预置常用模型列表 + 允许自定义输入（`el-select filterable allow-create`）。
5. 提供「测试连接」功能验证 key + 模型可用。
6. 配置界面：供应商卡片块 + 模型标签增删。

## 数据结构（两张表）

`user_llm_config`：每个供应商一个 api-key。

```sql
CREATE TABLE user_llm_config (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    provider VARCHAR(20) NOT NULL,   -- DASHSCOPE / DEEPSEEK
    api_key VARCHAR(255) NOT NULL,
    enabled TINYINT DEFAULT 1,
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_user_provider (user_id, provider),
    INDEX idx_user_id (user_id)
);
```

`user_llm_model`：该供应商下可配置的多个模型名。

```sql
CREATE TABLE user_llm_model (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    provider VARCHAR(20) NOT NULL,
    model_name VARCHAR(100) NOT NULL,
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_user_provider_model (user_id, provider, model_name),
    INDEX idx_user_id (user_id)
);
```

## 后端改动（`backend/my-agent`）

### 新增文件

| 文件 | 职责 |
|---|---|
| `entity/UserLlmConfig.java` | 供应商配置实体（provider + apiKey + enabled） |
| `entity/UserLlmModel.java` | 模型配置实体（provider + modelName） |
| `mapper/UserLlmConfigMapper.java` + XML | 供应商配置查询（selectByUserId / selectByUserIdAndProvider） |
| `mapper/UserLlmModelMapper.java` + XML | 模型查询（selectByUserId / selectByUserIdAndProvider / deleteByUserIdAndProvider） |
| `dto/UserLlmConfigDto.java` | 供应商视图对象：id, provider, providerLabel, apiKey(脱敏), enabled, models[], createTime, updateTime |
| `dto/UserLlmConfigRequest.java` | 入参：provider, apiKey(编辑留空保留), enabled, modelNames[](全量替换) |
| `service/UserLlmConfigService.java` + impl | CRUD + 模型全量替换 + 脱敏 + 缓存失效 |
| `controller/UserLlmConfigController.java` | `/llm-config` 接口（list/save/delete/test/presets） |
| `model/UserChatModelManager.java` | **核心**：按用户动态构建并缓存 ChatModel，测试连接 |
| `exception/LlmNotConfiguredException.java` | 未配置异常 |

### UserChatModelManager 核心设计

- 缓存 key = `userId:provider:modelName`（同一供应商不同模型是不同 ChatModel）。
- `ChatModel getChatModel(Long userId, ModelEnum model, String modelName)`：查 `user_llm_config` 拿 key，校验 enabled，动态构建。
  - DashScope：`new DashScopeApi(baseUrl, apiKey, null)` + `DashScopeChatOptions.builder().withModel(modelName).withProxyToolCalls(true)` + `new DashScopeChatModel(api, options)`。
  - DeepSeek：`OpenAiApi.builder().baseUrl(deepseekBaseUrl).apiKey(apiKey)` + `OpenAiChatModel.builder().defaultOptions(model(modelName))`。
- 无配置/禁用时抛 `LlmNotConfiguredException`。
- `invalidate(userId)`：配置增删改后清理该用户全部缓存。
- `testConnection(userId, provider, apiKey, modelName)`：非缓存构建 + `call(new Prompt("ping"))` 验证。

## 前端改动（`frontend/my-agent-frontend`）

| 文件 | 改动 |
|---|---|
| `api/llmConfig.js` | list / save / deleteByProvider / test / presets |
| `api/ai.js` | `doChatWithLoveAppSse`、`doChatWithManus` 增加 `modelName` 参数拼到 URL |
| `views/LlmConfig.vue` | 供应商卡片块：每个供应商填写 api-key + 启用开关 + 模型标签增删（预置列表 + 自定义），支持测试连接 / 删除配置 |

**预置模型**：DASHSCOPE → `[qwen-max, qwen-plus, qwen-turbo, qwen-flash]`；DEEPSEEK → `[deepseek-v4-pro, deepseek-v4-flash]`。

## 数据流

- 保存：`LlmConfig.vue` → `POST /llm-config/save`（provider + apiKey + modelNames[]）→ Service upsert config + 全量替换模型 → `invalidate(userId)`。
- 测试：`POST /llm-config/test` → `testConnection`（不入缓存）。
- 对话 chat：`/ai/my_app/chat/sse/one?model=qwen&modelName=xxx` → 按 (provider, modelName) 取缓存 ChatModel。
- 对话 agent：`/ai/manus/chat?model=...&modelName=...` → 同上，未配置发 error 事件。

## 边界情况

1. 未配置：chat 返回提示分块、agent 返回 error 事件，用户消息**不持久化**。
2. 编辑时 apiKey 留空：保留库中旧值；新增时 apiKey 必填。
3. 模型列表全量替换：编辑时前端提交完整模型列表，后端先删后插。
4. 禁用（enabled=0）：`getChatModel` 视为未配置。
5. 并发：每用户锁 + 双重检查。
6. key 安全：明文存库、接口脱敏、日志不打印。

## 验证方式

1. 后端 `mvn -q compile`、前端 `npm run build` 编译通过。
2. 接口级：登录 → 配置某供应商 key + 多个模型 → 测试连接 → list 确认 key 脱敏、models 列表 → 对话两种模式各选不同模型验证流式。
3. 未配置用户：chat 返回提示、agent 返回 error 事件。
